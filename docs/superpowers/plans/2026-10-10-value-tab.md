# Value Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Value" tab that shows each BTO unit's estimated resale value, range, gap vs the BTO price and its drivers.

**Architecture:** Geocode resale blocks once (OSM, then OneMap, cached); train scikit-learn gradient-boosted
models offline on resale sales with location features; precompute estimates per stack × floor into
`project.json["value"]`; the static app renders a Value tab from that.

**Tech Stack:** Python 3 + pandas/numpy + scikit-learn (new, offline only); vanilla JS ES modules; Playwright MCP.

**Spec:** `docs/superpowers/specs/2026-10-10-value-tab-design.md`

## Global Constraints

- Training data `reference/resale/resale.csv` (git-ignored); geocode cache `reference/resale/geocode.json` (git-ignored).
- Target log(price); features: flat type, floor area, flat model, storey midpoint, remaining lease years, month index,
  town, distances to nearest MRT/LRT, Raffles Place (lat 1.2839, lon 103.8515), nearest mall, nearest hawker centre,
  primary schools within 1 km.
- Validation: test = sales in the last 6 months before `asOf`; report MdAPE and 10–90 coverage; targets MdAPE ≤ 7%,
  coverage 70–90%; report, never hide.
- BTO estimate inputs: type, `prices[code].sqm`, most common flat model of that type among leases ≥ 2015, storey =
  floor, lease 94, month = asOf, block location.
- Copy: range label "a flat like this, resold today with ~94 years of lease left"; source line
  "Model trained on HDB resale transactions (data.gov.sg), 2017–<asOf>. Estimate, not a valuation."; Plus/Prime caveat as in spec.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A stack whose flat type has no resale equivalent (CCA, RENT, 3GEN with few sales): no estimate, row says so, no crash — Task 3 test.
- Upcoming project (no stacks, no prices): Value tab shows per-type estimates without a gap line — Task 4 Playwright step.
- Sales from blocks that fail geocoding: dropped and counted, never placed at a guessed location — Task 1 test.
- Switching Sun ↔ Value tabs keeps the selected unit and the 3D highlight — Task 4 Playwright step.
- Quantile crossing (lo > est or hi < est): clamp so lo ≤ est ≤ hi — Task 2 test.

### Task 2: Train and validate

**Files:** Create `tools/train_value.py`; extend `test/value_test.py`

**Interfaces:**
- `features(df: DataFrame, geo: dict, amen: list) -> DataFrame` (columns as Global Constraints; rows without
  coordinates dropped; returns also `dropped` count via `df.attrs['dropped']`);
- `storey_mid('10 TO 12') == 11`, `lease_years('61 years 04 months') == 61.33`;
- `fit(X, y) -> {'mid','lo','hi'}` models; `predict(models, X) -> (est, lo, hi)` arrays with lo ≤ est ≤ hi;
- writes `reference/resale/value-metrics.json` `{asOf, mdape, coverage, nTrain, nTest, dropped}`.

- [ ] Step 1: tests: `storey_mid`, `lease_years`; `predict` clamps a crossed quantile (synthetic models); a model fit
  on a 20k-row slice predicts its own held-out rows with MdAPE < 15%.
- [ ] Step 2: run → fail.
- [ ] Step 3: implement with `HistGradientBoostingRegressor` (categorical town/type/model via `categorical_features`),
  log target; time split per Global Constraints.
- [ ] Step 4: tests ok; run full training; record metrics vs targets in the ledger.
- [ ] Step 5: commit.
