# 3D Map Features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real 3D footprints for schools, community clubs, libraries, hawker centres, health buildings and parks;
ground-floor tints for clinics, supermarkets and preschools inside other buildings; and the new buildings blocking sun.

**Architecture:** `tools/fetch_surround.py` gains an island-wide cached OSM features query whose outlines become new
`P.surround` kinds, a new `P.blockers` list (feature buildings within the 900 m context radius) and `host` indices on
amenities. `web/project.js` appends `P.blockers` to the shading list; `web/scene.js` draws the new kinds and host rings.

**Tech Stack:** Python 3 stdlib (existing tools), three.js (existing), `node:assert` and Python asserts, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-17-3d-features-design.md`

## Global Constraints
- **No commits or pushes** until the user asks.
- Overpass: same User-Agent `BTOlab/1.0 (personal project)` and mirror retry as `osm_buildings()`; one **island-wide**
  query cached at `reference/amenities/osm-features.raw` (git-ignored like the other `*.raw`), bbox
  `(1.2,103.6,1.47,104.05)` as the existing query.
- Kinds and sources: `school` = `building=school`, plus `building=*` ways inside an `amenity=school` area; `campus` =
  the `amenity=school` area; `cc` = `amenity=community_centre`; `library` = `amenity=library`; `hawker` =
  `amenity=marketplace|food_court` areas; `health` = `amenity=hospital|clinic` areas (incl. polyclinics); `park` =
  `leisure=park`. Ways and multipolygon outer rings (largest), like the mall handling today.
- Heights: OSM `height`, or `building:levels × 4.0` (existing `LEVEL_M`); else school 12, cc 10, library 12,
  hawker 8, health 20; `campus` and `park` 0.2.
- Radius **1,500 m** for drawing (`RADIUS`); outlines simplified with the existing `simplify`; a new outline whose area
  overlaps an existing `hdb`/`mall`/`mrt` outline (or a `P.context` block) by **> 50%** of its own area is dropped.
- `P.blockers`: building kinds (`school`, `cc`, `library`, `hawker`, `health`) with centre within **900 m** (the
  `fetch_context` radius), each `{k, h, p}`. `P.context` is never modified (other code indexes it by position).
- Host tint: amenities with `cat` in `clinic`, `supermarket`, `preschool` get `host` = index into `P.surround` of the
  `hdb` or `mall` outline containing the point, else the nearest such outline within **15 m**; else no `host`.
  Note: HDB blocks inside the context extent are in `P.context`, not `P.surround` — hosts may be either; store
  `host: {"s": i}` for surround or `{"c": i}` for context.
- Colours from `web/nearby.js` `ACAT` (school/campus `primary` green, cc, library, hawker, health = `polyclinic`,
  park); ground areas at y = 0.15 (above map tiles, below everything else); host ring 4 m tall, 0.3 m outside.
- Existing budgets (`test/budget_test.py`), frame rate, and all tests keep passing.

## Review Focus
1. **An amenity point that falls inside both a mall and an HDB outline** (or two overlapping outlines) → one host,
   the smallest containing outline — test in Task 2.
2. **Multipolygon features with holes** (school campus with a courtyard) → outer ring only, no crash on missing
   member geometry — test in Task 1.
3. **A feature building straddling the 900 m blocker radius** → included/excluded by its centre, consistently with how
   `P.context` uses centres — test in Task 1.
4. **Shading regression:** adding blockers can only remove sun — for one project every unit's sun hours are ≤ before —
   test in Task 3.
5. **Projects with no features nearby** (empty lists) → nothing drawn, no errors, legend unchanged — test in Task 4.
